## 1. 阶段目标与验收门槛

**目标**：系统可供一个真实业务团队（10~20 人）试用，覆盖：完整 Web 界面、Agent 化问答、检索质量显著提升、可运维可审计。

**P1 验收标准（2026-08-16 实测）**：

1. 意图路由：4 类识别 + 闲聊拒答 3/3（黄金集 30 条）；
2. 检索基线：recall@5 = 0.852，MRR = 0.796（较 P0 的 0.833/0.722 提升）；
3. RAGAS：faithfulness = 0.894 ✅，answer_relevancy = 0.595（未达 0.75，待优化）；
4. 管理台：问答/文档管理/反馈全界面可用；
5. 回归门禁：app/eval/regression.py 生效（容差 0.05，劣化 exit 1）；
6. 审计日志：注册/登录/上传/删除/用户管理全程可查。

## 2. 工作拆分（按优先级）

### 2.1 Agent 化（LangGraph，最高价值）— FR-21/23/24/26

| 任务 | 说明 | 依赖 |
|---|---|---|
| 引入 LangGraph，service 升级为状态机图 | 节点：路由 → 改写 → 检索 → 反思 → 生成；保留现有 SSE 契约，API 不破坏 | — |
| 意图路由 | 四类：知识问答 / 文档总结 / 闲聊拒答 / 需澄清；LLM 结构化输出 + 规则兜底 | LangGraph |

## 4. 关键决策点（需评审）

1. **Agent 化是否引入 LangGraph**：P0 自研线性编排已可用；引入 LangGraph 换实现成本 vs 多跳/反思的可维护性收益（推荐：引入，服务层接口不变，风险可控）；
2. **OCR 优先级**：若试用团队无扫描件需求，OCR 可降级到 P2（标注 FR-10 灵活）；
3. **管理台技术栈**：Vue3 + Element Plus（技术栈既定），但 P1 是否含完整管理台或先做问答工作台 + 文档管理（推荐：分两期，W3 先交互核心）；
4. **试用范围**：P1 结束后选择哪个业务团队/知识库做灰度。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| LangGraph 迁移破坏现有链路 | 服务不可用 | 接口契约不变 + 图内保留线性路径回退开关 + 回归门禁先于迁移生效 |
| answer_relevancy 提升困难（judge 严格） | 验收不达标 | 提示词精简、judge 校准、评分规则向用户反馈对齐（FR-31 反馈数据辅助） |
| 管理台工作量膨胀 | 周期拉长 | W3/W4 拆分交付，先核心交互后管理功能 |
| 并发性能（50 并发） | 体验下降 | 检索/嵌入加缓存（Redis 热点查询）、LLM 流式连接池 |
| 试用期数据安全 | 合规风险 | 审计日志先行、试用环境权限收敛 |

## 6. 与 P2 的衔接

P2 候选（工具调用、connector 数据源、敏感信息脱敏、在线反馈回流自动化、GraphRAG 试点）在 P1 收尾时按试用反馈排序。
